## Architecture

The app is a SPA admin for a small warehouse. Folder structure is defined stage by stage — do not create folders a task does not ask for.

Routes are file-based in `src/routes/`; `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin and must not be edited by hand.

`src/domain/` holds zod schemas (one file per entity plus an `index.ts` barrel). TypeScript types are always inferred from schemas via `z.infer<>` — no duplicate hand-written types. Money fields (e.g. `price`) are stored in minor units (cents).

Route files export only `Route`; page components stay unexported in the route file or live outside `src/routes` (exporting anything else disables per-route code-splitting).

`src/mocks/db/` is the mock backend's in-memory database. All writes go through `transaction()` — never mutate the exposed readonly arrays directly. Bump `DB_VERSION` in `storage.ts` whenever the shape of stored data changes (old persisted data will be discarded and re-seeded).

**URL search state:** one thin hook per route (`useCatalogSearch`, `useJournalSearch`) built on `applySearchPatch` from `src/lib/search.ts`; never hardcode the list of keys that reset the page. Search schemas use `.catch` so invalid values are dropped; defaults are stripped from the URL with `stripSearchParams(DEFAULTS)`.

## Code style

- **Indentation:** 4 spaces (Prettier `tabWidth: 4`); JSON, YAML, and Markdown use 2. Prettier defaults otherwise (double quotes, semicolons).
- ESM only, TypeScript strict; use `import type` for type-only imports.
- Imports are enforced by `eslint-plugin-perfectionist`. Write them correctly from the start instead of relying on `eslint --fix`:
  - Two groups. First: packages and Node built-ins, preceded by the comment `// outsource dependencies`. Then one blank line. Second: relative imports, preceded by the comment `// local dependencies`. No blank lines inside a group.
  - Within each group, sort import lines by line length, shortest first (type and value imports are sorted together).
  - Inside braces, sort named imports by length, shortest first.
  - Side-effect imports (e.g. `import "./index.css";`, `import "@testing-library/jest-dom/vitest";`) go first in their group, right after the group comment. ESLint does not enforce their position (perfectionist leaves side-effect imports in place because their order can matter, e.g. the CSS cascade), so follow this rule manually.

```ts
// outsource dependencies
import { z } from "zod";
import type { ReactNode } from "react";
import { useState, useCallback } from "react";
import { createSlice, type PayloadAction } from "@reduxjs/toolkit";

// local dependencies
import "./styles.css";
import { api } from "./api";
import type { Product } from "../types";
import { formatPrice } from "../../utils/format";
```

## UI and theme

- Visual direction "Warehouse", light theme only. Tokens live in `src/index.css` (shadcn tokens plus `warning`, `stock-out` and `tooltip`); do not edit the `.dark` block.
- Use theme tokens through Tailwind classes (`bg-card`, `text-muted-foreground`, `bg-warning`, ...). No hex values or arbitrary colors in components.
- `font-sans` (IBM Plex Sans) for text; `font-mono` (IBM Plex Mono) for SKUs, numbers, breadcrumbs, table headers and status badges.
- Corners: `rounded-sm` for panels and controls.
- Reference screen: `/design-preview` (`src/components/design-preview/`) shows the catalog layout, panel and table header styles, the stock meter and the LOW/OUT badges. New screens follow it. It is static and will be removed when the real catalog replaces it: never import from it.
- **Layout:** `SidebarInset` is the scroll container (`h-dvh overflow-y-auto`); the window does not scroll. Pages that fill the visible height use `src/components/layout/FullHeightPage` (header / children / footer). Tables inside them: card `flex-1 min-h-0 overflow-hidden`, `Table` `containerClassName="h-full overflow-auto"`, sticky header row with an opaque background.
- **Shared UI:** `TablePagination` (`src/components`) for paginated tables, with a thin per-feature wrapper for prefetch and the out-of-range redirect; `ProductCombobox` lives in `src/components`.

## Data layer

`src/api/baseApi.ts` — `createApi` with `reducerPath: "api"` and four tag types: `Category`, `Product`, `Supplier`, `Movement`. The `baseQuery` wraps `fetchBaseQuery` (base URL `/api` resolved against `window.location.origin`), awaits `waitForBackend()` before every request (catching rejection → `{ status: "NETWORK_ERROR", code: "BACKEND_UNAVAILABLE" }`), and normalizes all other failures into `ApiErrorData` (`{ status, code, message, fields? }`) from `src/api/types.ts`.

`src/api/errors.ts` — `isApiErrorData(error)` type guard and `getErrorMessage(error: ApiErrorData | SerializedError | undefined)` helper for UI code.

`src/api/endpoints/` — one file per resource that calls `baseApi.injectEndpoints(...)` and exports the generated hooks. Tag lists provide `{ type, id: "LIST" }` plus one tag per item id; `resetDemo` invalidates all four tag types.

`src/api/queries.ts` — shared Zod query schemas (moved from the mock controllers) plus `paginationQuery`. Mock controllers and `createHandlers.ts` import the schemas at runtime for validation; client endpoint files import **only types** (`import type`) so Zod stays out of the main bundle via this path.

`src/api/backendReady.ts` — `setBackendReady(promise)` / `waitForBackend()`. `main.tsx` calls `setBackendReady` synchronously with the dynamic-import-chained promise before rendering; default is a resolved promise so tests proceed immediately.

`src/store/store.ts` — `makeStore()` wires the api reducer and middleware, calls `setupListeners`. `src/store/hooks.ts` — typed `useAppDispatch` and `useAppSelector` via `withTypes`.

- Mutations: `invalidatesTags` returns `[]` on error (never invalidate on a failed write).
- Movement dates from a local date + "now": use `combineLocalDateWithTime` (`src/lib/date.ts`), never `date + toISOString().slice(10)`.
- **Dates:** movement dates are stored as UTC ISO strings; filters and display use the user's local date (`toLocalIsoDate`, `formatLocalDate`). Never parse a date-only string with `new Date("YYYY-MM-DD")` — it is interpreted as UTC.

## Mock API

Requests flow: **MSW handler → `route()` (network simulation, validation, error mapping) → controller (pure function over the db)**.

- `src/mocks/api/route.ts` — `createRouteHandler({ db, network })` returns a bound `route(controller, options?)` function. `route()` returns an MSW resolver that handles delay, random-error injection, query/body validation with Zod, and error mapping.
- `src/mocks/api/createHandlers.ts` — `createHandlers({ db, network })` assembles all MSW handlers; contains no business logic.
- `src/mocks/api/controllers/` — one file per resource; each controller is a pure function `({ db, params, query, body }) => { status?, body? }`. Throw `ApiError` to signal client errors; any other throw becomes 500.
- `src/mocks/api/errors.ts` — `ApiError` class + helpers (`badRequest`, `notFound`, `conflict`, `unprocessable`). Error response shape: `{ error: { code, message, fields? } }`.
- `src/mocks/browser.ts` — creates the app-singleton `db` and MSW `worker`; not imported directly by `main.tsx`.
- `src/mocks/start.ts` — exports `mocksReady: Promise<void>` (dynamically imports `browser.ts` and starts the worker). The RTK Query `baseQuery` will `await mocksReady` before every request.
- `main.tsx` renders immediately without waiting for the worker; it kicks off `import("./mocks/start")` as a fire-and-forget and logs any start error.
- Network simulation config (`src/mocks/api/network.ts`): delay range, error rate/mode. Toggle error mode via `setErrorMode("random" | "off")`; persisted in `localStorage` under key `warehouse-manager:network`.

### Bundle analysis

```bash
ANALYZE=1 pnpm build   # writes stats.html (gitignored)
```

Open `stats.html` in a browser to see the interactive treemap. Main browser-chunk cost: `tldts` (TLD trie from MSW's `tough-cookie`) ≈ 111 KB gz, Zod ≈ 34 KB gz, `@mswjs/interceptors` ≈ 24 KB gz. The 500 kB build warning for the lazy `browser-*.js` chunk is expected — MSW pulls in `tldts` through `tough-cookie`; a 500 kB warning on any other chunk is a real problem.

## Receiving wizard

- **Step validation:** validation issues with an empty field path go to the form-level error (`{ form, fields }`), never to a parent array field like `"lines"` — a parent-field `onSubmit` error is not cleared by editing child fields and permanently blocks the next submit.
- **Server field errors (e.g. 409 `DUPLICATE_INVOICE`):** keep them in React state on the wizard and render through `FormField`; do not write TanStack field meta from async callbacks — the field may not be registered if its step was never rendered in this session (restored draft).
- **Focus after step change:** run in an effect after render (guarded by a ref), not in `queueMicrotask`.
- **Leaving the wizard programmatically** (success, Discard, Reset demo data): call `innerRef.cancelSync()` first, then discard the draft, then remount via `formKey` — otherwise the unmount flush writes the stale draft back.

## Working rules

- Do NOT commit or push; the developer commits after reviewing.
- Work on the current branch; never switch branches.
- Do not add dependencies the task does not ask for.
- For library and GitHub Action versions, check current releases (e.g. `pnpm view <pkg> version`, `gh release view --repo <owner/action>`) instead of relying on memory.
- Before reporting, run the available checks: `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.
- Report format: files changed (one line each), check results, anything skipped or not done.
- Wizard UI tests start from a draft pre-seeded in storage at the target step (see `ReceivingWizard.posting.test.tsx`) instead of typing through earlier steps.
- A test that pins a bug fix must be shown to fail without the fix before it is committed.
- A module-level `Intl.DateTimeFormat` keeps the time zone it was created in, so `vi.stubEnv("TZ")` has no effect on it: stub TZ, then `vi.resetModules()` and re-import the module dynamically.
- To pin "today", fake only the Date object: `vi.useFakeTimers({ toFake: ["Date"] })` + `vi.setSystemTime`; restore in `afterEach`.
- MSW 3: `server.listen({ onUnhandledFrame: "error" })` (`onUnhandledRequest` was renamed to `onUnhandledFrame`).
- Page sizes and counts in tests come from the `DEFAULTS` constants and the db, never from literals like `20`.
- When the same button exists in both the toolbar and an empty/error state, scope the query with `within()` on the state the scenario is testing.
